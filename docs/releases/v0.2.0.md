# clink-integ-cli v0.2.0 release candidate

Status: code-review candidate only. This change does not publish npm artifacts, create a GitHub Release, push a tag, or modify a production service or database.

## Breaking fixture contract

The default `webhook fixture` and generated `webhook simulate` payload now use the `merchant-webhook` profile:

- event IDs use the `event_` prefix
- `object` is `event`
- top-level `created` is a Unix-millisecond integer
- the complete resource is under the object-valued `data.object`
- the obsolete top-level `livemode` field is absent
- invoice lines use `items`, not `lineItems`
- subscription and invoice timestamps are Unix-millisecond integers
- subscription and invoice line-item amounts use decimal strings such as `"19.99"`
- `refund.succeeded` and `dispute.created` now have canonical merchant fixture resources for acceptance and local routing tests

The old flattened fixture is available only with `--fixture-profile legacy`. It emits a deprecation warning and is scheduled for removal in a future major release.

No `agent-callback` fixture profile is included in this release candidate. The repository does not contain a sufficiently documented Agent Callback fixture contract, so v0.2.0 does not invent one or flatten merchant subscription/invoice events into an Agent format.

## Runtime event presets

Every create, update, or ensure command that changes endpoint events first reads `GET /webhook/events` from the selected environment. Explicit events, CLI presets, and server aliases are validated against that runtime response.

- `core`: fixed compatibility set of 6 events; intentionally incomplete
- `checkout`: 9 events
- `subscriptions`: 14 events (11 subscription + 3 invoice)
- `disputes`: 5 events
- `payment-methods`: 3 currently public events
- `commerce`: 31 events in the current 44-event catalog
- `all`: all events returned by the runtime catalog

Presets are composable and de-duplicated. Missing required events fail instead of being silently removed. Stable `payment-methods` and `commerce` remain 3 and 31 events; if a newer runtime exposes `payment_method.deleted`, it can be selected explicitly and is included by dynamic `all`.

`--allow-unknown-events` remains accepted for command-line compatibility but is deprecated and no longer bypasses runtime catalog validation.

## Safer endpoint ensure

`webhook endpoint ensure` now defaults to safe merge semantics and reserves replacement for the explicit dangerous flag:

1. Fetch the runtime event catalog.
2. Query the existing endpoint by URL.
3. Read endpoint detail when a list summary omits events, and fail closed if the current set remains unknown.
4. Preserve existing events and add the resolved selection by default.
5. Use `--allow-remove-events` to replace the set; report added, removed, unchanged, and final events before a destructive PUT, and confirm again in interactive terminals.
6. Preflight local secret destinations, then PUT the ensure request.
7. Persist any newly returned secret, run an explicitly requested restart, then read the endpoint back and require its final event set to exactly match the computed merge or replacement target.

Dry-run still performs the read-only catalog and endpoint preflight requests, but it does not PUT or perform post-write verification.

## Endpoint safety and reliability

- API calls have a 30-second default timeout, configurable with `--timeout-ms` or `CLINK_API_TIMEOUT_MS`.
- CLI profile and env-file targets are checked before PUT; writes use temporary files plus atomic replacement, and a multi-destination failure rolls the env file back before returning non-zero.
- Captured `--restart-command` stdout, stderr, command text, and errors redact the complete signing secret.
- JSON output includes `requestedEvents`, `finalEvents`, `eventDiff`, and the verified endpoint.

## Generated webhook handlers

Next.js, Express, and FastAPI starters now:

- verify the signature against the untouched raw body before JSON parsing
- process canonical object-valued `data.object` directly
- normalize the explicit legacy string-valued `data.object` shape after verification
- convert legacy ISO `created` values to Unix milliseconds and `lineItems` to `items`
- emit a structured legacy warning metric containing only event ID and event type
- emit a structured error and return non-2xx for unknown payloads or event types
- leave an explicit integration point for the merchant's idempotent webhook Inbox and retry workflow

Only read-only sandbox/UAT catalog validation is permitted before approval. Do not perform destructive endpoint replacement in production.

## Sandbox/UAT validation status

- Local mock-API integration covers runtime catalog lookup, exact preset expansion, default merge, explicit replacement, idempotency, 4xx/5xx, network failure, request timeout, env updates and rollback, restart-output redaction, PUT, and post-write GET verification.
- A read-only sandbox `GET /webhook/events` attempt was made on 2026-08-05. The local environment had no configured sandbox Secret Key, and the API correctly returned `401 Unauthorized` without one.
- No sandbox endpoint was created or modified. An authenticated read-only catalog check remains pending until `CLINK_SECRET_KEY` is supplied through the local environment or CLI profile; the key must not be pasted into review notes or chat.
